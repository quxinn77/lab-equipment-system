# 后端任务分配（仅含缺失/实现错误项）

> 原则：多的不改，只改"没有的"和"不对的"。已实现且超出需求的模块（预约、报修、消息、统计、日志、实验室、分类、二维码、导入导出、逾期管理）一律不动。

---

## 后端 A — 设备库存模型 + 借用审批链路

| 序号 | 任务 | 优先级 | 改动点 | 涉及文件 |
|:---:|---|:---:|---|---|
| A1 | 设备表增加库存字段 | P0 | `device` 表加 `total_qty`（总库存，默认1）、`available_qty`（当前可借数，默认1） | `sql/schema.sql`、`backend/.../entity/Device.java` |
| A2 | Device DTO/VO 透出库存字段 | P0 | `DeviceDTO` 加 `totalQty`；`DeviceVO` 加 `totalQty`、`availableQty` | `backend/.../dto/DeviceDTO.java`、`backend/.../vo/DeviceVO.java` |
| A3 | 设备创建/编辑时设置库存 | P0 | `create()` 中 `availableQty = totalQty`（默认1）；`update()` 中同步更新 `totalQty`，可用数随之调整 | `backend/.../service/impl/DeviceServiceImpl.java` |
| A4 | 借用申请校验改为可借数判断 | P0 | `apply()` 中：`status==IDLE` 改为 `availableQty > 0`（仍排除 REPAIRING/SCRAPPED） | `backend/.../service/impl/BorrowServiceImpl.java` |
| A5 | 审批通过时可借数 -1 | P0 | `approve()` 同意分支：`device.availableQty -= 1`；若减到 0 则状态置 `BORROWED`，否则保持 `IDLE` | `backend/.../service/impl/BorrowServiceImpl.java` |
| A6 | 归还时可借数 +1 | P0 | `returnDevice()` 中：`device.availableQty += 1`；状态置回 `IDLE`（损坏除外，走报修） | `backend/.../service/impl/BorrowServiceImpl.java` |
| A7 | 简化借用状态机（去取件环节） | P1 | 需求流程 `PENDING→APPROVED→RETURNED`；移除/废弃 `pickup` 接口与 `BORROWED` 中间态，审批通过即视为借出（可借数 -1），学生直接归还 | `backend/.../controller/BorrowController.java`、`backend/.../service/impl/BorrowServiceImpl.java` |

## 后端 B — 学生自助归还 + 登出失效 + 冲突拦截修正

| 序号 | 任务 | 优先级 | 改动点 | 涉及文件 |
|:---:|---|:---:|---|---|
| B1 | 放开归还接口给学生本人 | P0 | `returnDevice` 接口去掉 `@RequireRole` 限制，改为 Service 内校验：**申请人本人** 或 管理员 可调用 | `backend/.../controller/BorrowController.java`、`backend/.../service/impl/BorrowServiceImpl.java` |
| B2 | 归还状态放宽到 APPROVED | P0 | `returnDevice()` 允许 `APPROVED` 状态直接归还（配合 A7 去取件环节）；同时保留对 `BORROWED/OVERDUE` 的兼容 | `backend/.../service/impl/BorrowServiceImpl.java` |
| B3 | 借用冲突拦截改为库存计算 | P0 | 按需求公式：`可借数 = 总库存 - (状态为 PENDING + APPROVED 的借用单数)`；`apply()` 中用此公式判断可借，替代单设备状态判断 | `backend/.../service/impl/BorrowServiceImpl.java` |
| B4 | 退出登录后端 Token 失效 | P1 | 新增 `POST /api/auth/logout`，将当前 token 加入黑名单（内存 Set 或 Redis）；`JwtInterceptor` 校验黑名单 | `backend/.../controller/AuthController.java`、`backend/.../interceptor/JwtInterceptor.java` |
| B5 | 前端我的借用页加"归还"按钮 | P0 | `MyBorrows.vue` 中 `APPROVED`（及 `BORROWED`）状态行增加"归还"按钮，弹出归还状况选择后调用归还接口 | `frontend/src/views/borrows/MyBorrows.vue` |
| B6 | 设备列表展示总库存/可借数 | P0 | `devices/List.vue` 表格增加"总库存""可借数"两列；状态标签逻辑：可借数>0 显示"可借"，=0 显示"已借完" | `frontend/src/views/devices/List.vue` |

---

## 协作说明

- **A7 与 B2 强关联**：A 简化状态机后，B 放开归还状态，两人需联调确认 `APPROVED → RETURNED` 路径通畅。
- **A4/A5/A6 与 B3 有重叠**：建议 A 先完成库存字段和可借数增减，B 再将 `apply()` 的判断改为库存公式（避免两人同时改 `apply()` 冲突）。
- **B5/B6 为前端任务**：可由任一后端人员兼做，或交给前端同学。
- **已实现的超出需求模块一律不动**。

## 改动优先级

1. 第一批（P0，必须完成）：A1、A2、A3、A4、A5、A6、B1、B2、B3、B5、B6
2. 第二批（P1，可选优化）：A7、B4
